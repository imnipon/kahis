Hoof Health — Logic / Rule (Spec for Dev)
Persistence (mockup)
· เครื่องใหม่ / เข้าครั้งแรก → โหลดชุดตัวอย่างจากไฟล์ใน GitHub
· Refresh ธรรมดา → คงข้อมูลที่แก้ในเบราว์เซอร์นี้ (localStorage)
· Hard reset → ล้าง localStorage แล้วโหลดชุดตัวอย่างจากไฟล์ที่เสิร์ฟอยู่ตอนนั้นใหม่
· อัปเดต seed บน GitHub ไม่ทับของในเครื่องอัตโนมัติ — ถ้าต้องการชุดใหม่ให้ Hard reset / ล้าง site data
คีย์: kahis.hoofHealth.data · ไม่ใช่ DB production
1. Clinical model
  • ขา (Limb): LF · RF · LH · RH
  • พื้นที่ (Side): Lateral · Medial · Interdigital — เรียงนี้ทั้งปุ่มเลือกและบล็อกสรุปใต้ภาพ
  • ต่อขา: (Zone 1–12 × Medial + Lateral) + Interdigital Zone 0, 10 = 26 terms
  • Lesion เก็บ ต่อโซน · แสดงโค้ดแบบ [SU] Sole Ulcer
  • Treatment (รอบนี้) เก็บ ต่อพื้นที่ (Lateral / Medial / Interdigital ของขานั้น) ไม่แยกต่อโซน — เพราะ wrap/trim/block มักทำระดับกีบ/ซอกกีบ · ถ้า product ต้องการ per-zone ต้องขยาย schema
  • Normal trim เป็น flag ระดับพื้นที่ (หรือทั้งขา) · ไม่วาดวงบนภาพ
2. Data shape (แนะนำ API / DB)
HoofRecord {
  id, animalHn, ownerNo, processOn, updatedAt, status: draft|done,
  dvm, dept, note,
  chart: {
    LF|RF|LH|RH: {
      lateral|medial: { normal: bool, zones: { "1"…"12": [lesionCode…] }, tx: [txCode…] },
      interdigital:   { normal: bool, zones: { "0":[], "10":[] }, tx: [txCode…] }
    }
  },
  photos: [{ id, url, leg, side, zone, uploadedAt }]
}
ChangeLogEntry { ts, ownerNo, hn, recordId, action, message, by }
// action ตัวอย่าง: view | new-record | confirm | apply | clear-leg | clear-side
3. UI flow
  • Entry: KAHIS shell + MOCKUP banner + Owner No. + ปุ่มแสดง · ยังไม่โชว์ตาราง
  • หลังแสดง: ซ่อน MOCKUP/Owner bar · แท็บตารางรวม + แท็บสัตว์
  • แท็บสัตว์: toolbar (Last Process / Update / Owner meta) · 3 คอลัมน์ Map | Select | Meta
  • ภาพซ้าย = display only · เลือกขา/พื้นที่/โซน/โค้ดได้เฉพาะบล็อกกลาง
  • ใต้ภาพ: 3 บล็อกสรุป Lateral / Medial / Interdigital ของขาที่เลือก
  • Record ที่ done แล้วถ้าแก้ → ปุ่มกลายเป็น Apply และเขียน Change Log
  • Change Log (หัวข้อบน) = ทั้ง Owner · History (ในแท็บสัตว์) = เฉพาะ HN นั้น
4. ผังภาพ · วง overlay · จุดแม่นยำ (สำคัญต่อ Dev)
  • พื้นหลังคงที่: NP/hoof_health/claw_zones_chart.png (อ้างอิง FIGURE 1) · วางเต็มความกว้างคอลัมน์ · ห้าม object-fit: cover ที่จะครอปภาพ
  • Overlay เป็น absolute layer ทับภาพ · พิกัดเป็น เปอร์เซ็นต์ของกรอบภาพ [x%, y%] จากมุมซ้ายบน → ขยายจอแล้วจุดไม่เพี้ยนถ้าอัตราส่วนภาพเดิม
  • ตารางจุดอยู่ใน JS คงที่ ZONE_HOTSPOTS คีย์รูปแบบ 'lateral:4', 'medial:7', 'interdigital:0'
  • วงแดง (ใน) = มี lesion ที่โซนนั้น · วงน้ำเงิน (นอก) = มี treatment ที่ พื้นที่นั้น และโซนนั้นมี lesion — ไม่โชว์วงตอนกดเลือกเลขอย่างเดียว · ไม่โชว์ Normal
  • Calibrate: ที่ภาพกด ⌥ Option + คลิก (Mac) → console แสดง hotspot: [x, y] → ใส่ใน ZONE_HOTSPOTS → refresh ตรวจซ้ำ
  • ถ้าเปลี่ยนไฟล์ภาพ / crop / สัดส่วน → ต้อง calibrate จุดใหม่ทั้งชุด

                         if lesion && side.tx.length → blue outer
5. Confirm / Apply / History / Change Log
  • Confirm: draft → done · ตั้ง updatedAt / confirmedAt
  • Apply: แก้ record ที่ done แล้ว · เก็บ audit ใน Change Log (ใคร แก้เมื่อไร อะไร)
  • สัตว์หนึ่งตัวมีได้หลาย Process on (ประวัติรอบปาดกีบ) เลือกจาก dropdown · นี่คือ record history
  • ปุ่ม History ในแท็บสัตว์ = filter Change Log ตาม HN · ปุ่ม Change Log บนหัว = ทั้ง Owner
ตัวอย่าง seed: Owner 3 ฟาร์ม · สัตว์หลายตัว · บางตัวมี 3–4 records (confirm → apply → follow-up) เช่น สายฝน HH-102-A/B/C · ดาวเรือง HH-301-A→D · เปิด Change Log / History ได้เลย
6. Persistence
  • เครื่องใหม่: ไม่มี localStorage → ใช้ seed ในไฟล์
  • Hard reset: ล้าง LS แล้วโหลด seed จากไฟล์ที่เสิร์ฟอยู่ (หลัง pull GitHub = ชุดล่าสุด)
  • อัปเดต GitHub ไม่ re-seed อัตโนมัติ — กันการทับงานที่ลองแก้ไว้ · ล้างเองเมื่อต้องการ
  • Draft ที่ยังไม่ Confirm ยังไม่เขียนลง record จนกว่าจะ Confirm/Apply
  • Production → API + DB
7. สี UI พื้นที่
  • Lateral = น้ำเงิน · Medial = ส้ม · Interdigital = ม่วง (ปุ่ม + บล็อกสรุปใต้ภาพใช้ชุดเดียวกัน)
